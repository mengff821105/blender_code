# Feature Specification: Blender 到 Unity 批量 FBX 导出插件

**Feature Branch**: `001-unity-fbx-exporter`

**Created**: 2026-11-07

**Status**: Draft

**Input**: User description: "做一个 Blender 到 Unity 的批量 FBX 导出插件：支持每个物体/每个集合/合并三种导出模式，自动应用 Unity 轴向预设（-Z forward, Y up），支持前后缀命名、Apply Transform、应用修改器、网格过滤、输出目录记忆、错误提示和打开输出目录。非目标：glTF、多套预设、云同步。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 按物体批量导出（Priority: P1）

用户在场景中选中若干网格物体，一键将每个物体分别导出为独立的 FBX 文件，文件的轴向、
缩放和坐标约定符合 Unity 的导入要求，拖入 Unity 项目后无需手动修正朝向和比例。

**Why this priority**: 这是插件存在的核心理由——替代"选中一个、手动导出、手动改轴向参数"
的重复劳动；没有它，产品不成立。

**Independent Test**: 选中 3 个独立物体执行导出，检查输出目录生成 3 个 FBX，分别只包含
对应物体，且导入 Unity 后朝向、缩放正确。

**Acceptance Scenarios**:

1. **Given** 场景中有 3 个选中的网格物体，**When** 用户选择"每个物体"模式并点击导出，
   **Then** 输出目录生成 3 个以物体名命名的 FBX，每个文件只包含对应物体。
2. **Given** 导出完成的 FBX 被拖入 Unity 项目，**When** 用户把模型放入场景，
   **Then** 模型正面朝向正确（无 90 度轴向偏差）、缩放为 1 倍（无巨大化或微小化）。
3. **Given** 物体带有修改器（如镜像、细分），**When** 开启"应用修改器"后导出，
   **Then** FBX 中呈现修改器计算后的最终形态。

---

### User Story 2 - 按集合批量导出（Priority: P1）

用户按集合组织场景资产，希望每个集合导出为一个 FBX，集合内所有物体包含在同一文件中，
一次操作完成整个项目的资产拆分导出。

**Why this priority**: 与 P1 同属核心批量能力，真实项目里集合是标准的资产组织单位，
缺失它会迫使有项目结构的用户退回手工导出。

**Independent Test**: 建立含 2 个集合（其中一个含嵌套子集合）的场景，选中相关物体后
按集合导出，检查每个集合对应一个 FBX 且内容完整不串组。

**Acceptance Scenarios**:

1. **Given** 场景中有集合 A（含 2 个物体）和集合 B（含 1 个物体），**When** 用户选择
   "每个集合"模式导出，**Then** 生成 A、B 两个 FBX，分别包含各自集合的全部物体。
2. **Given** 一个集合嵌套了子集合，**When** 执行集合模式导出，**Then** 父集合文件包含
   其层级下所有后代物体，且不与其他集合的文件内容重复。
3. **Given** 某个选中物体不属于任何集合，**When** 执行集合模式导出，**Then** 系统给出
   明确提示告知被跳过的物体数量，其余集合正常导出，不崩溃。

---

### User Story 3 - 合并为单个 FBX（Priority: P2）

用户希望把选中的所有物体打包导出为一个 FBX（如整套场景道具、一个组合机械件），
文件名由用户指定。

**Why this priority**: 常见但频次低于前两种模式，实现上复用同一导出管线，成本低。

**Independent Test**: 选中多个物体执行合并导出，检查只生成 1 个 FBX 且包含全部选中物体。

**Acceptance Scenarios**:

1. **Given** 选中 5 个物体，**When** 用户选择"合并为一个"模式、文件名填 `engine_parts`
   并导出，**Then** 输出目录只生成 `engine_parts.fbx`，内含全部 5 个物体且相对位置不变。
2. **Given** 用户未填写合并文件名，**When** 点击导出，**Then** 系统提示文件名必填，
   不产生空名文件。

---

### User Story 4 - 命名与导出选项控制（Priority: P2）

用户需要统一给导出文件加前缀/后缀以符合 Unity 项目的资产命名规范，并可选择导出前是否
应用变换、是否应用修改器、是否只导出网格物体。

**Why this priority**: 决定产物能否直接进入团队项目管线，影响专业用户的采用，但不影响
"能导出"这一基本价值。

**Independent Test**: 设置前缀 `SM_`、后缀 `_v1` 导出，检查文件名符合规则；切换三个
开关分别导出，检查结果与开关语义一致。

**Acceptance Scenarios**:

1. **Given** 物体名为 `bolt`，**When** 设置前缀 `SM_`、后缀 `_v1` 后导出，
   **Then** 文件名为 `SM_bolt_v1.fbx`。
2. **Given** 选中物体中混有灯光和相机，**When** 开启"只导出网格物体"导出，
   **Then** 灯光和相机被跳过，FBX 只含网格；关闭该开关时则按软件原生行为处理。
3. **Given** 物体有非均匀缩放，**When** 开启"导出前 Apply Transform"导出，
   **Then** 导出的文件中物体变换被烘焙，进 Unity 后缩放显示为 (1,1,1)。
4. **Given** 物体名包含文件系统非法字符（如 `*`、`:`、`?`），**When** 导出，
   **Then** 非法字符被安全替换（下划线），导出成功且界面提示替换情况。

---

### User Story 5 - 输出目录管理与错误反馈（Priority: P2）

用户希望输出目录被记住，下次打开插件不用重选；导出过程中任何异常都得到看得懂的提示，
导出成功后可以一键打开输出目录查看文件。

**Why this priority**: 决定日常使用的流畅度和信任感；没有防御式错误处理的批量工具会
在异常场景下损坏用户的工作节奏。

**Independent Test**: 设置一次输出目录后保存重开场景，确认目录仍在；分别触发"未选物体"
"目录不存在"等异常，确认提示可读；点击打开目录按钮能在系统文件管理器中定位。

**Acceptance Scenarios**:

1. **Given** 用户设置过输出目录，**When** 保存并重新打开场景，**Then** 输出目录设置
   仍然保留。
2. **Given** 没有选中任何物体，**When** 用户点击导出，**Then** 弹出中文提示"请先选择
   至少一个物体"，不执行导出、不报错崩溃。
3. **Given** 输出目录路径不存在或无写入权限，**When** 点击导出，**Then** 系统提示
   具体原因（目录不存在/无写入权限），不产生半成品文件。
4. **Given** 导出成功，**When** 用户点击"打开输出目录"，**Then** 系统文件管理器打开
   该目录并定位到导出文件所在位置。
5. **Given** 一次批量导出完成，**When** 操作结束，**Then** 状态栏报告成功导出的文件
   数量，且场景中用户原本的选中状态与导出前完全一致。

---

### User Story 6 - 撤销与场景安全（Priority: P3）

导出过程中插件为达成导出效果对场景做的临时性修改（如临时选择、应用变换），不得污染
用户场景；所有对场景数据的持久改动都必须可通过撤销恢复。

**Why this priority**: 属于专业度保障而非新能力，放在最后，但违反它会直接导致差评。

**Independent Test**: 导出后检查选择状态；对执行了 Apply Transform 的物体按撤销，
确认场景恢复导出前状态。

**Acceptance Scenarios**:

1. **Given** 用户选中物体 A、B、C，**When** 批量导出完成，**Then** A、B、C 仍处于
   选中状态，活动物体不变。
2. **Given** 导出时启用了 Apply Transform，**When** 用户执行撤销操作，**Then** 物体的
   位置/旋转/缩放恢复到导出前的值。
3. **Given** 导出中途被用户取消或发生错误，**When** 操作中止，**Then** 场景选择状态
   还原，已生成的部分文件情况在提示中说明。

### Edge Cases

- 未选中任何物体就点击导出：必须拦截并给出中文提示。
- 选中集合中包含空集合（无任何物体）：跳过并在结果报告中说明，不产生 0 字节文件。
- 物体名经过前后缀拼接后与现有文件重名：在文件名后追加序号（`_1`、`_2`），不静默覆盖。
- 输出目录是相对路径且场景从未保存过：提示用户先保存场景或改用绝对路径。
- 物体名包含空格、中文或文件系统非法字符：空格与中文保留，非法字符替换为下划线并提示。
- 场景物体数量很大（50+）时的批量导出：允许操作在后台串行执行，界面不卡死，结束后统一报告。
- Blender 版本低于声明的最低兼容版本：插件不启用或启用时给出版本不兼容提示。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 提供三种导出模式：每个选中物体一个文件、每个集合一个文件、
  全部选中物体合并为一个文件。
- **FR-002**: 系统 MUST 以 Unity 约定的坐标变换参数导出 FBX：前向轴 -Z、上轴 Y，
  保证导入 Unity 后无需手动修正朝向。
- **FR-003**: 系统 MUST 支持用户为导出文件名统一配置前缀和后缀，预览效果可从命名规则推断。
- **FR-004**: 系统 MUST 提供"导出前应用变换（Apply Transform）"开关，开启时把物体的
  位置/旋转/缩放烘焙进导出数据。
- **FR-005**: 系统 MUST 提供"应用修改器"开关，开启时导出修改器的计算结果而非原始网格。
- **FR-006**: 系统 MUST 提供"只导出网格物体"开关，开启时跳过灯光、相机、空物体等
  非网格对象，并报告跳过数量。
- **FR-007**: 系统 MUST 持久化用户的输出目录与全部选项设置，重新打开场景后自动恢复。
- **FR-008**: 系统 MUST 在导出前校验选中对象、输出目录有效性和文件名合法性，
  任何校验失败都以可理解的中文提示安全中止，不得出现未捕获错误。
- **FR-009**: 系统 MUST 在导出完成后报告成功文件数、跳过对象数及文件名替换情况，
  并提供一键打开输出目录的操作入口。
- **FR-010**: 系统 MUST 保证导出结束后场景的选中状态与导出前一致。
- **FR-011**: 系统对场景数据的任何持久修改 MUST 支持撤销；临时性操作 MUST 在导出
  完成后自动还原。
- **FR-012**: 系统 MUST 处理文件名冲突，通过追加序号避免覆盖已有文件。
- **FR-013**: 系统 MUST 在界面上声明兼容的软件版本范围，并在不兼容版本运行时给出提示。

### Key Entities *(include if feature involves data)*

- **导出设置（Export Settings）**：用户在面板上配置的全部参数集合——输出目录、导出模式、
  合并文件名、前缀、后缀、三个开关；随场景保存，是插件唯一的持久化用户数据。
- **导出任务（Export Job）**：一次点击导出所对应的执行单元，包含目标对象分组结果、
  每个分组的目标文件名、执行状态与结果报告（成功数、跳过数、警告列表）。
- **命名规则（Naming Rule）**：前缀 + 源名称（物体名或集合名）+ 后缀的文件名生成约定，
  含非法字符清洗与重名序号追加两条子规则。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 用户完成"选择 5 个物体 → 批量导出为 5 个独立 FBX"全流程的操作时间
  不超过 30 秒（不含软件导出计算耗时），而手工逐个导出同等任务需要 5 分钟以上。
- **SC-002**: 导出的 FBX 在 Unity 中一次导入成功率达到 100%：轴向、缩放无需任何
  手动修正（以验收测试场景为准）。
- **SC-003**: 首次使用的用户不看文档，仅凭界面文字能在 5 分钟内成功完成第一次
  批量导出（验收时由至少 1 名非开发人员盲测）。
- **SC-004**: 验收测试场景中的全部边界用例（未选物体、空集合、非法字符、重名、
  目录无效、取消导出）100% 给出中文提示且无崩溃、无场景污染。
- **SC-005**: 导出完成后场景选中状态还原正确率 100%，Apply Transform 类操作的
  撤销可用率 100%。
- **SC-006**: 50 个物体规模的批量导出过程中界面保持可响应（不出现系统"无响应"），
  最终文件数量与内容全部正确。

## Assumptions

- 目标用户是使用 Blender 制作资产、再导入 Unity 的个人开发者或小团队，具备基础的
  3D 软件操作能力，能自行在 Unity 中执行导入操作。
- 输出格式仅支持 FBX；glTF/GLB、USD 等格式明确排除在本版本范围之外。
- 导出设置随场景保存（场景级持久化）即可满足需求，不需要跨项目的多套命名/参数预设，
  也不需要云端同步。
- 集合嵌套的默认归组规则：父集合导出包含全部后代物体，物体按其最直接所属的用户集合
  参与分组；不属于任何集合的物体在集合模式下跳过并提示。
- 合并模式默认文件名为用户必填项，不提供按时间戳自动命名。
- 用户使用兼容声明范围内的 Blender LTS 版本（4.2 及以上）和处于官方支持期的 Unity 版本；
  老版本软件的兼容不作为本版本目标。
- 验收用的 Unity 测试项目为一个新建的空白通用渲染管线（URP/Built-in 均可）项目，
  不依赖任何第三方插件。
- 不处理版本管理（如 Perforce、Git LFS）对导出文件的锁定场景，假定输出目录可正常写入。
